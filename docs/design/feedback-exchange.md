# Feedback exchange reference layout

Uses Michelle’s newer reference: a left sidebar for Browse projects, Michelle’s picks, My requests, and How it works; a large two-column project gallery; a slim Waiting for feedback / All projects switch and search. The current eyes, exact headline **Good projects need fresh eyes.**, subtitle **Make your ideas real. Get feedback & Help someone make their project better.**, and prominent yellow **Submit your project** button remain in their current arrangement. The headline and subtitle now use the bundled Windows 93 `sserife` pixel font (bold for the headline), matching the window chrome. Project title bars use Georgia bold, with the title once per card. Desktop visitors get the restored 48px retro arrow and hand cursors throughout the site; editable fields retain the native text caret and disabled buttons use the arrow. Touch layouts do not enable custom cursor rules.

The permanent closer-look pane is removed. The whole card opens the project’s full detail and review view directly. A small underlined Take a look arrow signals that action; there are no extra window controls or chunky thumbnail buttons. Screenshots have more space, with brief summaries below. Legacy audience text is clamped visually to three lines until the owner adds a summary. Waiting for feedback prioritizes under-reviewed projects; All projects shows newest first. The sidebar keeps picks and personal requests separate from those two browsing orders.

The account popup is a compact builder card with a blue-purple pixel title bar, pink portrait panel, three-segment credit progress, actual reviews/useful-review counts, and a review action showing the one-credit completion reward. Launch-free submission status is explained separately from saved credits. Portrait editing, an active review, admin moderation and sign-out remain available. The sidebar has its own layer above the gallery so the popup and controls cannot disappear beneath thumbnails. Its measured position stays between the page title bar and desktop taskbar, including a compact placement for short landscape viewports. The body scrolls when needed while the title bar and review/sign-out actions stay visible. Short landscape screens scroll the whole card under its sticky title bar, keeping every control reachable. Close, Escape and outside clicks dismiss it; opening the portrait dialog keeps its existing behavior. Motion respects reduced-motion preferences. On smaller screens the sidebar becomes a compact navigation row with an account menu; cards stack on phones and the yellow submit action fills the width. The page has no decorative footer slogan or rules strip. How it works is a dedicated sidebar view containing the existing credit, assignment, reporting and moderation explanation. The surrounding desktop taskbar is unchanged.

When there are no real public submissions, four explicitly fictional examples demonstrate the layout. They are not inserted into Supabase, have no external project links, and cannot earn credits, receive public replies, be reported, or be featured by a moderator. Once real submissions exist, they replace the example board. Existing screenshot assets, icons, forms, account behavior, moderation and database permissions are preserved.

The built-in image generation tool produced the transparent eyes and four fictional interface previews. Optimized WebP files live in `public/feedback/`; the full prompt set is in [feedback-image-prompts.json](./feedback-image-prompts.json). Existing homepage artwork and shared fonts are preserved. Moderation remains publish first: signed-in members can report projects, reviews, and replies; moderators can remove or restore them afterward.

New submissions include a required one-sentence project summary (15–180 characters). The gallery shows that summary under the preview; “Who is it for?” remains separate in the full project brief. Search includes both summary and audience. Older projects retain their original gallery text until their owner adds a summary through “Add project summary” in the full project view. Owners can edit the summary without submitting again or spending credits. Existing open forms remain compatible through the older submission RPC.

CollegeVine-inspired review improvements: an initial impression and three required observations, each naming where, what happened, and what would help. Both API and database enforce lengths and distinct observations. Task outcome and design clarity remain. A complete published review earns one credit immediately; the first ten projects submit free, then requests cost three credits. Builders can mark or unmark individual observations useful (legacy reviews can be marked as a whole). Only the project owner can do this. Repeated marks and several useful observations on one review count as one helpful review and never add credits. Public reviewer activity shows completed and useful reviews; a compact community panel recognizes the top five by useful reviews. Helpful reviewer recognition requires useful reviews for at least three distinct builders. Hidden reviews/projects do not contribute to public reputation; restoring them restores it. Private tables and verified-member checks remain. Assignments still last 45 minutes and prioritize under-reviewed projects; they are distributed rather than exclusive reservations. The form now shows the deadline, can release an assignment, and can renew an expired assignment without replacing its draft. Inline annotations and extra quality credits are not part of this change.

While the initial project list is fetched, only a looping segmented blue activity bar appears below the filters. There is no nested window, folder illustration or visible caption. A screen-reader status announces loading, and reduced-motion visitors get a stationary bar. It ends as soon as the real request settles, with no simulated percentage or minimum wait. The yellow submission action remains available above the gallery.

## Project images

New submissions require one screenshot or cover image. JPG, PNG and still WebP originals up to 10 MB are resized in the browser before upload; the server decodes them again, strips metadata and stores a WebP up to 1600 pixels on its longest edge and 1 MB. The form previews the gallery’s top-aligned crop; a wide 16:9 image is recommended.

Existing projects remain valid without an image. Their owners can use “Add or change project image” in their full project view. Cover changes do not create a new request or charge credits.

The private `feedback-covers` bucket has owner-scoped, one-hour upload tickets and a ten-upload daily cap. Only covers attached to published projects are readable anonymously. Replaced, unattached and removed-project covers stay private. The same-origin delivery endpoint uses a 60-second cache, so moderation changes can take up to a minute to reach cached copies. No service-role key is used. Unattached files are retained privately; a future retention job may remove those after a grace period.

Apply `202610280005_feedback_covers.sql` with the matching release: its seven-argument submission RPC requires a cover and revokes authenticated access to the legacy six-argument RPC. `supabase/tests/feedback-covers.sql` is rollback-only and checks ownership, storage RLS, visibility, replacement, moderation, expiry and rate limits.
