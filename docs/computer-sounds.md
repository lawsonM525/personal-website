# Computer sound effects

Public computer pages use six short, original synthesized cues: click, open, close, minimize, maximize and startup. Window buttons select their matching cue; restore/taskbar/search/form invitation controls use open; navigation uses open; other buttons use the short click. Restart plays the startup chime. There is no hover, drag, typing or background loop sound.

The speaker control in the shared top bar is icon-only, keyboard accessible, and has a pressed state and mute/enable tooltip. Sound is enabled by default but the AudioContext is created only during an explicit trusted interaction. Initial automatic boot is silent. This follows the [Web Audio user-gesture guidance](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices). Muting immediately silences active playback, and the preference is stored under `michelle-computer-sound-v1`. Reloads, ordinary page navigation and storage changes in another tab preserve it. Storage or audio failures never block a page action.

`lib/computer-sounds.ts` renders the original mono PCM from sine/triangle notes with short attack/release envelopes. All individual cues are under half a second. A shared master gain is 0.4; buffers are cached per actual device sample rate. Rapid events are throttled and live sources are bounded. Backgrounding the tab stops active sounds; unmounting the public sound provider closes the context and discards buffers.

No system audio samples, external audio downloads, additional service, API key, microphone, recording or audio permissions are used. The sounds are inspired by the retro operating-system interaction pattern, rather than reusing Windows93 or Microsoft recordings. Primary shared navigation uses Next Link so a sound can finish during a page transition. Restart uses the existing client router when returning from another public page.

Proposal routes (`/begin/*`, `/begin`, `/openaibeta`) remain outside the sound provider, have no sound control and are unchanged. Remote Tally iframe interactions do not bubble into the website sound controller. A tone indicates a UI action, never a completed signup or sent message.

Validation: six audio tests cover finite/non-silent/unclipped PCM at 22.05, 44.1 and 48 kHz; lazy initialization; mute of current/pending playback; blocked/unsupported audio; rapid events; and disposal during resume. Three existing Tally tests pass. Route smoke checks require the sound control on public pages and its absence on proposals. Browser checks verify real Web Audio running state and cue selection, reload/navigation mute persistence, continuous context on primary navigation, keyboard mute, 320px phone geometry, and real signup fields without entering or submitting data. Hosted evidence is stored separately with the preview URL.
